HOW THIS APPLICATION WORKS

How It Works — 3-Step Process

1. SCRAPE
Fetches all active commercial vehicle listings from SGCarMart.com using a Cloudflare-bypass scraper. Saves each listing's model, year, price, depreciation, and dealer. Takes ~3–5 minutes.
2. COMPARE
Compares today's listing URLs against yesterday's. Any URL present yesterday but missing today = vehicle sold or delisted. Data is matched from the Listing Cache (captured while still active).
3. SOLD LOG
Sold vehicles are written to the Sold Log with full details — model, year, depreciation, price, dealer — from cache. SGCarMart removes this data from the listing once sold, so caching is essential.

Listing Cache — Why It Matters

Once a vehicle is sold, SGCarMart removes its price and depreciation from the listing page (shows "N.A."). To preserve this data, every active listing is cached during each scrape. When the sold detection runs, it first looks up the cache (Layer 0) to recover the full details — no data is ever lost.

Why Compare Instead of Scraping Sold Directly?

SGCarMart's avl=s (sold) filter only shows that a vehicle was sold — it does not show the price or depreciation at the time of sale. The only way to get accurate historical data is to capture it while the vehicle is still active, then detect the sale by comparing consecutive days.

Dashboard Guide

  • REFRESH DATA — Triggers a full scrape. Takes 3–5 minutes. A loading overlay shows the elapsed time and estimated time remaining. All tables auto-update when done.
  • Daily Report Table — Shows vehicles sold on the selected date, grouped by vehicle category (Van Diesel, Van Petrol, Truck, Bus, etc.). Navigate using the date arrows or date picker.
  • History Dropdown — Jump to any past date with sold data. The number shows units sold on that day.
  • Active Listings — Depreciation/Units by Year — Today's market: depreciation range and listing count per model per year.
  • Sold Listings — Last 60 Days — How many units of each model were sold in the last 60 days, broken down by year.
  • Export (CSV / Excel / PDF) — Download any table in your preferred format directly from each section.
  • Auto Schedule — Set once and the server scrapes automatically every day at your chosen time (SGT). No manual action needed.
  • Backup & Restore — Download the full database as a .db file before redeploying. Upload it after to restore all data instantly.
  • REST API — Access all data programmatically via /api/v1/docs.

Important Notes

  • You need at least 2 consecutive days of successful scrapes before sold detection produces results. The first scrape only saves active listings — there is nothing to compare against yet.
  • If a scrape fails mid-way (e.g. Cloudflare blocks), sold detection is skipped for that day to prevent false positives.
  • The server must stay running for the auto-schedule to fire. On Coolify this is always on.
  • Depreciation and price in sold records always reflect the last cached value while active — never the sold page, which shows "N.A.".
Best Practice: Schedule the scrape at a consistent time daily (e.g. 07:00 SGT). This ensures clean day-over-day comparison and minimises missed sales.
